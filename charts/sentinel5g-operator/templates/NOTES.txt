Sentinel5G operator installed into namespace "{{ .Release.Namespace }}".

Apply a TelecomSecurityPolicy to start protecting a workload, e.g.:

  kubectl apply -f config/samples/security_v1alpha1_telecomsecuritypolicy.yaml

Check status:

  kubectl get telecomsecuritypolicies -A

The SCORING column is whether the AI engine has ever published a score. It
reads False after {{ .Values.config.scoringPipelineGrace }} if the scoring
half of the system isn't running -- the AI engine is a separate chart
(charts/sentinel5g-ai-engine) and is NOT installed by this one:

  helm install sentinel5g-ai-engine charts/sentinel5g-ai-engine -n {{ .Release.Namespace }} \
    --set nats.url={{ .Values.nats.url }}

Without it every policy sits at Phase: Monitoring forever, and until the
SCORING column existed that looked identical to a healthy, quiet cluster.

{{- if not .Values.ebpf.enabled }}

NOTE: eBPF enforcement is disabled (ebpf.enabled=false). That covers BOTH
drop actions -- actions.ebpfBlock (per source IP) and actions.ebpfBlockTunnel
(per GTP-U tunnel, i.e. one subscriber rather than everyone behind the peer
gNB). The operator still reconciles policies and can drive mesh-layer
isolation, but neither drop reaches the XDP layer until you set
ebpf.enabled=true (the chart then adds ebpf.capabilities -- CAP_BPF +
CAP_NET_ADMIN by default; override on pre-5.8 kernels). See docs/integrations.md.
{{- end }}
{{- if and .Values.ebpf.enabled (not .Values.ebpf.pinPath) }}

NOTE: ebpf.pinPath is empty, so the enforcement maps are NOT pinned to
bpffs. Every active drop is lost whenever this Pod restarts (a helm
upgrade, an OOM kill, a node drain), while each policy's status goes on
claiming the blocks are in force. The operator re-applies them from status
within config.blocklistReconcileInterval ({{ .Values.config.blocklistReconcileInterval }}),
and once at startup, so the gap is bounded -- but it is a real gap. Watch
sentinel5g_ebpf_enforcement_pinned and sentinel5g_blocklist_drift_total
(docs/observability.md).
{{- end }}
{{- if and .Values.ebpf.enabled .Values.ebpf.pinPath }}

NOTE: the enforcement maps are pinned at {{ .Values.ebpf.pinPath }}, which
requires {{ dir .Values.ebpf.pinPath }} to be a bpf filesystem on every node
this runs on (`mount | grep /sys/fs/bpf`). If it is not, the Pod will fail
to schedule on the hostPath, or -- where the path exists but is not bpffs --
the operator attaches UNPINNED and records an EBPFPinUnavailable warning
Event rather than giving up enforcement entirely. Confirm with
`kubectl exec deploy/{{ include "sentinel5g-operator.fullname" . }} -- wget -qO- localhost:8080/metrics | grep enforcement_pinned`.
{{- end }}
